# Daneel.AI 🤖

**Daneel.AI** (Р. Даниел Оливо) — это локальный автономный ИИ-агент с открытой архитектурой. Проект ориентирован на абсолютную приватность, работу в офлайн-режиме (on-premise) и постепенное расширение под домашние и корпоративные задачи.

## 🎯 Цель MVP
Создать минимальный рабочий протокол общения "Пользователь ⇄ Агент ⇄ Локальная LLM" на чистом Python с возможностью дальнейшего превращения в мультиагентную систему.

## 🛠️ Стек технологий
* **Язык:** Python 3.10+ (для разработки используется 3.12, см. `.python-version`)
* **Управление зависимостями:** [uv](https://docs.astral.sh/uv/) — быстрый менеджер пакетов и виртуальных окружений
* **Среда запуска моделей:** [Ollama](https://ollama.com)
* **Базовая модель:** `qwen2.5:1.5b` (быстрая, легковесная, для тестов) или `llama3.2:3b`
* **HTTP-клиент:** `httpx` (асинхронные запросы и потоковый ответ Ollama)
* **Интерфейс:** [Textual](https://textual.textualize.io/) — локальный терминальный UI (TUI)
* **Тесты:** `pytest` + `pytest-asyncio`

## 🚀 Быстрый старт

1. Установите [uv](https://docs.astral.sh/uv/getting-started/installation/), а также установите и запустите Ollama. Скачайте модель в терминале:
   ```bash
   ollama run qwen2.5:1.5b
   ```
2. Клонируйте проект и установите зависимости (uv автоматически создаст `.venv` и поставит версии из `uv.lock`):
   ```bash
   uv sync
   ```
3. Запустите агента (откроется TUI):
   ```bash
   uv run daneel
   ```
   или напрямую:
   ```bash
   uv run python main.py
   ```

   В TUI: **Enter** — отправить сообщение (многострочный текст можно вставить из буфера), **Ctrl+L** — очистить диалог, **Ctrl+C** — выход. Для простого текстового режима без полноэкранного интерфейса:
   ```bash
   uv run daneel --cli
   ```

## 🧩 Устройство кода
* `daneel/core.py` — работа с Ollama через `/api/chat` с `stream: true`, история сообщений и обработка ошибок.
* `daneel/tui.py` — тонкий слой Textual: лог переписки, поле ввода, потоковый вывод ответа.
* `main.py` — точка входа; `--cli` включает простой текстовый режим.

Логика общения с моделью отделена от интерфейса, поэтому позже можно добавить другой UI или воркеров, не переписывая ядро. Тесты ядра и TUI запускаются командой:
```bash
uv run pytest
```

## 📦 Работа с зависимостями
Все зависимости описаны в `pyproject.toml`, точные версии зафиксированы в `uv.lock`.

```bash
uv add <пакет>          # добавить зависимость
uv lock --upgrade       # обновить все пакеты до последних совместимых версий
uv sync                 # пересобрать окружение под lock-файл
```

Файл `uv.lock` следует коммитить в репозиторий — это гарантирует воспроизводимость окружения.

## 💻 Разработка в VS Code
Настройки рабочей области (`.vscode/settings.json`) указывают Python/Pylance использовать интерпретатор из `.venv`. Если Pylance не видит установленные пакеты (`httpx`, `textual`), выполните **Python: Select Interpreter** → `.venv` и перезагрузите окно.

## 🤖 Навыки агентов (OpenCode)

Набор [навыков](https://github.com/mattpocock/skills) для планирования и разработки ставится **локально** и в репозиторий не коммитится (`.agents/skills/` и `skills-lock.json` в `.gitignore`). При настройке нового окружения выполните:

```bash
npx --yes skills@latest add mattpocock/skills -a opencode \
  --skill setup-matt-pocock-skills --skill grill-with-docs --skill grilling \
  --skill domain-modeling --skill to-spec --skill to-tickets \
  --skill implement --skill tdd --skill codebase-design \
  --skill code-review --skill diagnosing-bugs -y
```

Для обновления повторите команду `add` целиком — она перезапишет локальные копии. `npx skills@latest update` обновит только те навыки, которые попали в локальный `skills-lock.json` (он не коммитится), поэтому полный `add` надёжнее.

Типовой цикл работы над фичей (навыки вызываются через `@skill-id`):

1. `@setup-matt-pocock-skills` — один раз на репозиторий, создаёт конфигурацию агентов (для этого репозитория уже выполнено).
2. `@grill-with-docs` — детальное интервью по задаче, глоссарий и ADR.
3. `@to-spec` — спека в `.scratch/<feature>/spec.md`.
4. `@to-tickets` — тикеты в `.scratch/<feature>/issues/`.
5. `@implement` — реализация через TDD с финальным код-ревью.

Эти md-файлы, а также `AGENTS.md`, `docs/agents/*.md`, `GLOSSARY.md` и `docs/adr/` коммитятся в репозиторий — так контекст и решения синхронизируются между всеми разработчиками. Подробности конвенций — в `docs/agents/issue-tracker.md` и `docs/agents/domain.md`.
