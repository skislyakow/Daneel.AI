# Стандарты написания кода

Этот документ — канонический свод правил проекта. Он используется разработчиками и агентами, в том числе осью Standards навыка `code-review`. `AGENTS.md` содержит те же правила в сокращённой форме как оперативную шпаргалку; при расхождении приоритет у этого файла.

## Язык

- Код, комментарии и докстринги пишутся на английском языке.
- `README.md` — на английском, остальные markdown-файлы — на русском.
- Строки интерфейса живут в `daneel/i18n.py` на обоих поддерживаемых языках. Не хардкодьте пользовательский текст в TUI или CLI.
- Сообщения коммитов — на английском, в формате `<type>: <summary>` (`feat`, `fix`, `chore`, `build`, `docs`, `refactor`, `test`).

## Архитектура

- Интерфейс живёт в `daneel/tui.py`, логика Ollama и история разговора — в `daneel/core.py`. Не переносите HTTP-код в TUI.
- Строки интерфейса, разрешение языка и системный промпт находятся в `daneel/i18n.py`.
- Настройки окружения (`OLLAMA_BASE_URL`, `DANEEL_MODEL`, `DANEEL_WORKSPACE`, `DANEEL_LANG`, `DANEEL_REPLY`, `DANEEL_THEME`, `DANEEL_SESSION_DB`) собираются в `daneel/config.py`; CLI-флаги имеют приоритет. Значения по умолчанию объявляются в `config.py` в одном месте, остальные модули читают их оттуда.
- История сессий хранится в SQLite через `daneel/storage.py`. Только этот модуль работает с БД; `Conversation` и TUI не должны содержать SQL. Автосохранение происходит после каждого завершённого обмена.
- Ответы Ollama потоковые (`stream: true`); новые адаптеры должны потреблять `Conversation.stream_answer()`.
- Темы описаны в `daneel/theme.py`: фирменные `daneel`/`daneel-light` плюс встроенные Textual. Шрифт задаёт терминал — приложение его не меняет.
- Инструменты описаны в `daneel/tools/`; по умолчанию их нет, а подтверждение обязательно. Не добавляйте тихое выполнение операций: `ToolRegistry.call()` должен отклонять вызов без подтверждения.
- `DANEEL_WORKSPACE` — граница для будущих файловых операций; не используйте для этого текущий каталог «по умолчанию».
- Язык интерфейса по умолчанию английский, язык ответов — `auto` (ответ на языке сообщения пользователя). Переключение: `/lang`, `/reply`, `Ctrl+T`. Горячие клавиши имеют алиасы для русской раскладки (`Ctrl+Е/Д/С`), нижняя панель — свой локализованный `Static`, не штатный `Footer`.
- Все системные сообщения (смена языка/темы/режима ответов, справка, ошибки команд, отказ инструмента, результат копирования) показываются через `self.notify()` всплывающим уведомлением справа сверху на 2 секунды, а не строкой в чате и не в транскрипте `/copy`.
- Буфер обмена читается только через `daneel/clipboard.py`: системный буфер (`pyperclip`) с молчаливым фолбэком на внутренний `app.clipboard`. Правый клик по полю ввода вставляет без уведомления, правый клик по логу копирует выделение.
- Поле ввода — `PromptInput(TextArea)`, многострочное и динамически расширяется до 12 строк; Enter отправляет сообщение, Shift+Enter добавляет перевод строки.

## Проектирование модулей

- Стремитесь к глубоким модулям: много поведения за небольшим интерфейсом. Уменьшайте число параметров и методов, если это можно сделать без потери смысла.
- Используйте существующие seams (точки тестирования через публичный интерфейс) вместо создания новых. Для логики агента это `Conversation.stream_events()` и внедрённый `httpx.AsyncClient`; для инструментов — `ToolRegistry.call()`; для TUI — `App.run_test()`.
- Зависимости принимайте через интерфейс, а не создавайте внутри модуля. Не добавляйте абстракции «на будущее» без реальной потребности.
- Если модуль только пересылает вызовы дальше, примените тест удаления: если сложность исчезает вместе с ним, он не нужен.

## Тесты

- После изменений в `daneel/` запускайте `uv run pytest`.
- Тесты проверяют поведение через публичный интерфейс, а не внутренние детали. HTTP-запросы подменяются через `httpx.MockTransport`, TUI проверяется через `run_test()`.
- Работайте циклами red → green: сначала падающий тест на одной вертикальной связи, затем минимальный код для его прохождения. Не пишите все тесты заранее.
- Полный набор тестов запускается один раз в конце работы; по ходу отдельные файлы — чаще.

## Документация и трекер

- Задачи и спеки хранятся как markdown в `.scratch/<feature>/`; соглашения описаны в `docs/agents/issue-tracker.md`.
- Глоссарий и ADR создаются лениво, когда появляется реальное решение или термин; см. `docs/agents/domain.md`. Не создавайте их заранее «на всякий случай».
- `uv.lock` коммитится вместе с `pyproject.toml`: он гарантирует воспроизводимое окружение.
- Локальные настройки редактора (`.vscode/`) и установленные навыки агентов не коммитятся.
