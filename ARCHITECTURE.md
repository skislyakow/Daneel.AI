# Архитектура Daneel.AI

На текущем этапе проект придерживается **минималистичного процедурного стиля** для прозрачности отладки. Логика общения с моделью отделена от интерфейса: ядро не знает про TUI, а TUI не знает про HTTP.

## 🗺️ Текущая схема (MVP)
`Пользователь` ➔ `daneel/tui.py (Textual: ввод, вывод, команды /lang и /reply)` ➔ `daneel/core.py (история + httpx-поток + цикл tool_calls)` ➔ `Ollama /api/chat` ➔ `Потоковый ответ в TUI`. Строки интерфейса и язык ответов задаёт `daneel/i18n.py`, настройки окружения — `daneel/config.py`, операции — `daneel/tools/`.

## 📈 План эволюции в Мультиагентную систему
В будущем архитектура разделится на независимые роли (скрипты в папке `agents/`):
1. **Daneel_Router** — анализирует запрос пользователя и решает, кому его передать (домашние дела или корпоративные задачи).
2. **Daneel_Worker_Home** — модуль для личного использования (заметки, напоминания).
3. **Daneel_Worker_Corp** — модуль для работы (анализ логов, парсинг документов, генерация писем).

## 🗂️ Структура папок (MVP)
* `main.py` — точка входа: запускает TUI или текстовый режим (`--cli`).
* `daneel/core.py` — ядро: `OllamaClient` (потоковый `/api/chat`), `Conversation` (история) и цикл вызова инструментов.
* `daneel/clipboard.py` — чтение системного буфера с фолбэком на внутренний буфер приложения.
* `daneel/commands.py` — реестр слеш-команд и их аргументов; используется всплывающей палитрой.
* `daneel/storage.py` — SQLite-хранилище сессий: таблицы `sessions` и `messages`, внешний ключ и индекс по порядку сообщений.
* `daneel/config.py` — настройки из окружения с приоритетом CLI-флагов.
* `daneel/i18n.py` — локализация интерфейса, разрешение языка и сборка системного промпта.
* `daneel/theme.py` — фирменные темы, разрешение имени темы и регистрация в Textual.
* `daneel/tools/` — контракт инструмента, реестр и обязательное подтверждение вызовов.
* `daneel/tui.py` — терминальный интерфейс на Textual: многострочное поле ввода с динамической высотой, локализованные подсказки и команды.
* `tests/` — тесты ядра, конфигурации, локализации, тем, инструментов, хранилища и TUI с подставным HTTP-транспортом.
* `pyproject.toml` — метаданные проекта и зависимости (управляются через uv).
* `uv.lock` — зафиксированные версии зависимостей.
* `AGENTS.md` — постоянные инструкции для агентов разработки.
* `docs/agents/` — конвенции трекера задач и доменных документов.
* `.scratch/<feature>/` — спеки и тикеты фич в markdown (локальный трекер).
* `README.md` — описание проекта (на английском).
* `ARCHITECTURE.md` — архитектурный гайд.

## 🌐 Языки

Интерфейс по умолчанию английский (`--lang`, `DANEEL_LANG`, `/lang`, `Ctrl+T`). Язык ответов агента настраивается отдельно (`--reply`, `/reply`): `auto` — ответ на языке сообщения пользователя, `en`/`ru` — фиксированный язык. Код, комментарии и докстринги на английском; md-файлы, кроме README, — на русском.

Горячие клавиши дублируются алиасами для русской раскладки: `Ctrl+T`/`Ctrl+Е`, `Ctrl+L`/`Ctrl+Д`, `Ctrl+C`/`Ctrl+С`. Строка подсказок внизу — собственный локализованный `Static`, а не штатный `Footer` Textual.

При вводе `/` над полем появляется popup со всеми командами из `daneel/commands.py`; дальше список фильтруется по префиксу. Стрелки двигают подсветку, Enter подставляет команду (следующий Enter запускает её), Escape скрывает меню, клик мышью тоже подставляет команду.

Тема интерфейса задаётся `--theme`, `DANEEL_THEME` или командой `/theme <имя>`; `/theme` без аргумента показывает список. Есть две фирменные темы (`daneel`, `daneel-light`) плюс встроенные темы Textual. Шрифт задаёт терминал, приложение его не меняет.

## 🌍 Глобальный запуск и настройки

Основной способ запуска — `uv tool install --editable .`, после чего `daneel` доступен из любого каталога. Настройки читаются из `OLLAMA_BASE_URL`, `DANEEL_MODEL`, `DANEEL_WORKSPACE`, `DANEEL_LANG`, `DANEEL_REPLY`, `DANEEL_THEME`, `DANEEL_SESSION_DB`, `DANEEL_ENABLE_FS_TOOLS`; CLI-флаги перекрывают окружение.

## 💾 История сессий

Сессии и сообщения хранятся в SQLite (`daneel/storage.py`), путь задаётся `DANEEL_SESSION_DB` или `platformdirs`. Автосохранение после каждого обмена; `/sessions` открывает палитру сессий: Enter загружает выбранную, Delete или клик по значку ✕ удаляет с подтверждением. `/new` начинает новую сессию, палитра команд открывается по `/`, Escape её закрывает. `Conversation` не знает про БД — Storage является адаптером уровня приложения.

## 🛠️ Инструменты

В ядре есть каркас function calling: Ollama возвращает `tool_calls`, реестр выполняет инструменты и добавляет результаты ролью `tool`. По умолчанию зарегистрирован `get_weather` (`daneel/tools/weather.py`): геокодинг и прогноз через Open-Meteo без API-ключа. При `DANEEL_ENABLE_FS_TOOLS=1` добавляются `list_directory` и `read_file` из `daneel/tools/filesystem.py`: только чтение, пути резолвятся через `Path.resolve()` и проверяются на `is_relative_to(DANEEL_WORKSPACE)`, есть лимиты на число записей и размер файла. Вызов без подтверждения отклоняется. Десктоп-интеграция (горячая клавиша/трей) остаётся будущим адаптером.
