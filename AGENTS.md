## Agent skills

### Issue tracker

Задачи и спеки хранятся как markdown в `.scratch/<feature>/`. См. `docs/agents/issue-tracker.md`.

### Domain docs

Один контекст: `GLOSSARY.md` и `docs/adr/` в корне репозитория. См. `docs/agents/domain.md`.

## Команды

- `uv run pytest` — запускать после изменений в `daneel/`.
- `uv run daneel` — TUI; `uv run daneel --cli` — простой текстовый режим.
- `uv run daneel --lang ru --reply ru` — русский интерфейс и русские ответы агента.
- `uv run daneel --theme dracula` — выбрать тему; в TUI — `/theme <имя>` или `/theme` для списка.
- В TUI: `/sessions` открывает палитру сессий; Enter загружает выбранную, Delete или клик по значку ✕ справа удаляет с подтверждением. `/new` — новая сессия; палитра команд открывается по `/`, Escape её закрывает. Сайдбара нет, отдельных команд `/load` и `/help` нет.
- `uv tool install --editable .` — глобальная команда `daneel` из любого каталога.

## Архитектура

- Интерфейс живёт в `daneel/tui.py`, логика Ollama и история — в `daneel/core.py`. Не переноси HTTP-код в TUI.
- Строки интерфейса, разрешение языка и системный промпт находятся в `daneel/i18n.py`.
- Ответы Ollama потоковые (`stream: true`); новые адаптеры должны потреблять `Conversation.stream_answer()`.
- Настройки окружения (`OLLAMA_BASE_URL`, `DANEEL_MODEL`, `DANEEL_WORKSPACE`, `DANEEL_LANG`, `DANEEL_REPLY`, `DANEEL_THEME`, `DANEEL_SESSION_DB`, `DANEEL_ENABLE_FS_TOOLS`, `DANEEL_THINK`, `DANEEL_ROUTER`, `DANEEL_NUM_CTX`, `DANEEL_NUM_PREDICT`, `DANEEL_TEMPERATURE`, `DANEEL_KEEP_ALIVE`) собираются в `daneel/config.py`; CLI-флаги имеют приоритет. Локальный `.env` в корне проекта загружается автоматически, но реальные переменные окружения его перекрывают; `.env` в git не коммитится; в нём намеренно не задаётся `DANEEL_WORKSPACE`, чтобы рабочая директория была каталогом запуска. Язык интерфейса, язык ответов, тема, модель, режим думания и режим роутера сохраняются в `settings.json` из user config dir (`platformdirs`); изменения из TUI и явные env/CLI-значения перезаписывают файл.
- История сессий — в `daneel/storage.py` (SQLite); SQL только в этом модуле, автосохранение после каждого обмена.
- Темы описаны в `daneel/theme.py`: фирменные `daneel`/`daneel-light` плюс встроенные Textual. Шрифт задаёт терминал — приложение его не меняет.
- Инструменты описаны в `daneel/tools/`; по умолчанию включён `tools/weather.py` (`get_weather`, Open-Meteo без ключа), при `DANEEL_ENABLE_FS_TOOLS=1` добавляются `tools/filesystem.py` (`list_directory`, `read_file`) — только чтение в границах workspace. Встроенные инструменты выполняются без подтверждения (`requires_confirmation=False`). Реестр всё равно поддерживает обязательное подтверждение для будущих инструментов: `ToolRegistry.call()` отклоняет вызов без подтверждения, если инструмент сам этого требует.
- `DANEEL_WORKSPACE` — граница для файловых операций; по умолчанию это каталог запуска (`Path.cwd()`), а не папка с исходниками. Инструменты обязаны проверять `is_relative_to(workspace)` после `resolve()`.
- Код, комментарии и докстринги — на английском; `README.md` — на английском, остальные md-файлы — на русском.
- Язык интерфейса по умолчанию английский, язык ответов — `auto` (ответ на языке сообщения пользователя). Переключение: `/lang`, `/reply`, `Ctrl+T`.
- Слеш-меню строится из реестра `daneel/commands.py`: при `/` показываются все команды в две колонки (команда + приглушённое описание), фильтр по префиксу; Enter/клик открывает палитру аргументов, а для команд без аргументов — сразу выполняет команду. В палитре аргументов набор буквы фильтрует значения, Enter применяет выбранное сразу, Escape скрывает панель. В палитре сессий справа рисуется значок ✕ (удаление по клику или по Delete, всегда с подтверждением). Рамки у панелей нет: боковые полосы задаёт переменная темы `menu-edge` из `daneel/theme.py`, для встроенных тем есть фолбэк в `DaneelApp`.
- Горячие клавиши имеют алиасы для русской раскладки (`Ctrl+Е/Д/С`), нижняя панель подсказок удалена. Во время работы под строкой ответа в логе показывается анимированный золотистый счётчик «◌ Thinking · <model> · 2s / ◌ Думаю · <model> · 2с», после ответа та же строка меняется на «● Thought · <model> · 2s / ● Думал · <model> · 2с»; текущая рабочая директория постоянно видна внизу (`#workspace`).

## Стандарты кода

Полный свод правил — `CODING_STANDARDS.md`. При расхождении с этой шпаргалкой приоритет у него.

- Запросы уходят с `think: false`, `options(num_ctx=4096, num_predict=512, temperature=0.4)` и `keep_alive=30m`; это ускоряет отклик.
- `/model` — палитра моделей из `/api/tags`, `/think on|off` — рассуждения, `/router auto|manual` — эвристический выбор между `qwen2.5:1.5b` и `qwen3.5:4b`. Ручной `/model` отключает авто-роутер до `/router auto`. Инструменты всегда идут на тяжёлую модель.

- Лог автоматически следует за выводом, пока пользователь не прокрутил его вручную; после ручной прокрутки авто-следование выключается, `/latest` возвращает к последнему сообщению.
