# Копирование чата и выделенных фрагментов

## Проблема

Пользователь не может перенести переписку с агентом в другой документ: в терминальном интерфейсе нет команды, которая копирует весь чат, и нет действия, которое копирует текст, выделенный мышью внутри ленты сообщений.

## Решение

Правый клик по выделенному тексту копирует выделенный фрагмент в системный буфер. Команда `/copy` копирует весь видимый транскрипт чата в том виде, в каком он показан пользователю: сообщения, ошибки и системные заметки. Команда `/copy last` копирует только последний ответ агента. После любой операции показывается локализованная заметка «Скопировано»; если выделить нечего или чат пуст — соответствующая заметка. Ограничение OSC52 принимается: приложение всегда сообщает об успехе, даже если терминал не поддержал запись в буфер.

## Истории пользователей

1. Пользователю нужно выделять мышью часть чата и копировать её правой кнопкой, чтобы вставить конкретный ответ или ошибку в другой документ.
2. Пользователю нужно копировать весь видимый транскрипт командой `/copy`, чтобы сохранить сессию.
3. Пользователю нужно копировать только последний ответ агента командой `/copy last`, чтобы быстро переиспользовать его.
4. Пользователю нужна локализованная заметка после копирования или при отсутствии выделения, чтобы понимать, что произошло.
5. Русскоязычному пользователю нужно то же поведение на русском языке, чтобы интерфейс оставался согласованным.
6. Разработчику нужно проверять поведение через существующий механизм приложения и локальный буфер, чтобы не требовать реальный терминал.
7. Разработчику нужно, чтобы очистка чата очищала и источник копирования, поэтому `/copy` никогда не возвращает устаревший текст.

## Решения по реализации

- Интерфейс хранит чистый текстовый транскрипт отображаемых сообщений, ошибок и системных заметок; приветственный баннер в него не входит.
- Обработчик правого клика читает текущее выделение через публичный API экрана и копирует его через clipboard-API приложения; при отсутствии выделения показывается локализованная заметка.
- `/copy` копирует транскрипт, `/copy last` — последнюю строку агента, пустой транскрипт даёт локализованную заметку.
- Справка по командам и строка использования дополняются описанием `/copy`.
- Все новые строки интерфейса добавляются в модуль локализации на обоих языках.
- Новые зависимости, запись в файлы и изменения в ядре разговора не требуются.

## Решения по тестированию

Хороший тест наблюдает поведение через публичный интерфейс: нажимает клавиши и кнопки мыши, затем проверяет локальный буфер приложения, а не внутренние списки и структуру виджетов.

- Копирование по правому клику проверяется передачей выделенного текста через публичный API выделения экрана и кликом правой кнопкой.
- `/copy` и `/copy last` проверяются отправкой сообщений через поле ввода, вызовом команды и чтением буфера.
- Случаи пустого выделения и пустого чата проверяются тем же способом.
- Локализованные заметки проверяются через выделение всего текста экрана и чтение выделенного фрагмента.
- Ранее в тестах интерфейса уже используются механизм запуска приложения и mock HTTP-транспорт; следуем этим образцам.

## Вне скоупа

- Клавиатурный дубль для копирования (Ctrl+Y и подобные).
- Копирование сырой истории разговора вместо видимого транскрипта.
- Сохранение транскрипта в файл.
- Изменение системного промпта, инструментов и доменных документов.

## Дополнительные заметки

Две возможности независимы: копирование правым кликом работает с любым выделенным текстом, а `/copy` работает с транскриптом, который накапливает интерфейс.

## Уточнение после реализации

Короткие ответы о результате копирования («Скопировано», «Нечего копировать», «Ничего не выделено») показываются всплывающим уведомлением в правом верхнем углу, которое исчезает через 2 секунды, а не дополнительной строкой в чате. Это не добавляет шум в транскрипт, который копирует `/copy`. Правый клик читает выделение на `MouseDown`: Textual очищает выделение на `MouseUp` до события `Click`.

Правый клик по полю ввода вставляет текст в курсор без уведомления. Сначала читается системный буфер через `pyperclip`; на Linux без `xclip`/`xsel`/`wl-copy` и в headless-сессиях молча используется внутренний буфер Daneel. Оба буфера пусты — вставка ничего не делает.

Поле ввода заменено на многострочное (`TextArea`): оно динамически расширяется до 12 строк, Enter отправляет весь текст сообщением, Shift+Enter добавляет перевод строки. Это убирает проблему невидимого многострочного текста и «залипшего» placeholder однострочного `Input`.
